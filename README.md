# 创新实践及科研训练·企业运营模拟（企业1专属版）

![版本](https://img.shields.io/badge/版本-0.2.0-blue)

## 项目概述

创新实践及科研训练·企业运营模拟是一款基于现代Web技术开发的企业运营模拟软件，用于《创新实践及科研训练》（创新创业实践）课程教学。系统模拟企业1全流程运营，帮助学生理解企业管理的核心概念和运营逻辑，提升综合管理能力和决策水平。

按课程要求，本系统为**企业1专属版**：仅保留企业1作为唯一运营主体，无多企业竞争设定；广告投放规则采用课程修改项（一次投放覆盖本地+区域市场、P1+P2产品）；本期运营仅开放 P1/P2 产品与 P2 研发。

### 核心功能

- **财务中心**：现金流量可视化、长/短期贷款（含还本付息生命周期）、资金贴现（7:1）、应付税金下年初交纳、年度利润表
- **生产中心**：厂房与生产线管理（购买分期付款、转产、出售残值规则）、厂房购买/租赁/出售、P2 分期研发（1M/季×6季）、折旧计提
- **物流中心**：原材料采购（R1/R2提前1季、R3/R4提前2季，到货入库付款）、库存管理
- **营销中心**：市场开拓（年度投资模型+维持规则）、ISO认证、广告投放（修改后规则）、订货会订单池、订单交付
- **运营流程**：年初/季度/年末操作步骤、季度推进、第四年结束模拟
- **运行控制表**：按年导出 `第X年运行控制表.csv`（年初4项+季度20项×4+年末6项，按课程格式填充数据；单企业设定下不适用的"向其他企业购买/出售原材料、成品"两行保留并在行名标注不启用理由）
- **存档流转**：存档包导出/导入（默认不覆盖、先预览）、账实重演算核对、核对报告导出
- **教学辅助**：内置规则说明弹窗、运营暂停/继续（讲解模式）、存档（自动+手动）、操作日志导出

## 使用说明

### 系统初始状态（遵循课程标准）

- **财务**：现金20M，应收账款15M（4Q账期），长期贷款40M，应交税1M；总资产105M = 负债41M + 权益64M
- **生产**：大厂房（自有40M）+ 小厂房（租赁3M/年）各1个，各配1条全自动生产线（设备净值合计13M）；P1在制品4个
- **物流**：R1原料3个，P1成品3个
- **营销**：本地市场准入，P1生产资格；区域/国内/亚洲/国际市场与ISO9000/ISO14000均未取得

### 运营流程

1. **年初**：新年度规划会议 → 投放广告 + 参加订货会（生成订单池）→ 制定新年度计划 → 支付应付税
2. **季度**：季初盘点 → 短贷还本付息 → 原料下单/到货 → 生产（开工投料+加工费1M）→ 交货 → 研发/行政费等
3. **年末**：长贷付息/还本 → 设备维护费 → 厂房购买/租赁（第4季度决策）与厂房租金 → 计提折旧 → 市场开拓/ISO投资（各1M/年，未维护则丧失市场）→ 结账（利润表与所得税计入应付税金）
4. **导出**：运营流程页可随时导出已完成年度的运行控制表 CSV

### 关键规则（含课程修改项）

- **广告（修改项）**：投放一次同时覆盖本地+区域市场、P1+P2产品；金额决定可选订单数量（每1M解锁2张）；仅年初第1季度可投放
- **贷款**：长贷年末申请（3年期10%，每次20M最多40M）；短贷Q1/Q3放贷（1年期5%，到期一次还本付息）；无高利贷
- **贴现**：应收款随时可贴现，7M付1M贴息
- **市场开拓**：年末操作，1M/年/市场，可中断；已准入市场每年投1M维持，否则放弃
- **厂房交易**：年末购买/新租（大40M/5M年、小30M/3M年），任意季度可出售已腾空的自有厂房（按原值计入4Q应收款，可贴现；第4年第2季度起的出售在模拟结束前收不到现，款项留在应收账款中）；厂房不提折旧，买卖与租约本身不进利润表（租金仍计入综合费用）

详细规则见系统内"规则说明"弹窗。

### 存档流转与完整性校验

**操作路径**：主界面右上角 `存档管理` → `导出存档包` / `导入存档包`；选完文件后出现的**导入预览面板**内另有 `导出核对报告（txt）` / `导出核对报告（json）` 与两个落库按钮。

- **导出**：下载 `企业1存档-第X年第Y季-YYYYMMDDHHmm.json`（`packageFileName`），内容是 `current` 当前进度 + `saves` 全部历史快照 + `digests` 两类指纹（包指纹、逐帧指纹）。JSON **不带 BOM**（`serializePackage` 就是 `JSON.stringify`），脚本可按 `parseSavePackage`（`src/utils/savePackage.ts`）的同一套结构规则读取与校验。
- **导入**：先出预览——当前屏读数、逐帧账实重演算结论、指纹判定、分歧起点、口径说明——预览阶段**不改动本机任何状态**（存档列表、当前屏、本地存储都不动）。落库由二选一决定：`仅加入存档列表`（与本机同 id 的帧不替换，追加新 id 形如 `-imported-1`、列表名加注 `（导入1）`，原有存档一个字节不动）或 `设为当前进度`（只换当前屏，不自动并入列表）。
- **暂停态的取舍**：导出、选文件、算预览、导核对报告都是只读动作，运营暂停时照常可用；只有上面那两个会写本机存档的动作要先"继续运营"。
- **体积**：解析层的入场闸是 8MB（`MAX_PACKAGE_BYTES`；UTF-16 码元数与 UTF-8 字节数**任一**超限即拒，报「文件过大（超过 8MB），不是合法存档包」）；落库写 localStorage 时配额约 5MB，写入失败会被接住并说明"本次导入未落库、原有存档未改动"。实测体积见 `docs/roadmap.md` §3 P0。

**存档格式版本**由 `src/types/enterprise.ts` 的常量 `SAVE_FORMAT_VERSION` 单点定义（当前 4），包里的 `app.saveVersion` 与每帧的 `version` 都引用它，文档与代码都不写裸数字。各版本含义：v1/v2 为早期形态（无贷款台账；v1 的原料到货季度是 1~4 循环值，跨年即错），v3 加入厂房权属与租赁快照，v4 加入财务日志的 `kind`（`flow`/`summary`）分类。旧档在**载入时**由 `migrateState` 补齐缺失字段，v3→v4 还会按 `src/utils/restatement.ts` 的新口径（重述串＝自上一条重述串以来的全部净变动）就地重建重述串链；`loadGame` 与导入侧的版本门统一写成 `version >= SAVE_FORMAT_VERSION`，未达标的存档会提示"旧版存档已迁移至v4，建议重置开新局"。

### 完整性校验的能力边界

> 完整性校验用于发现误操作与随手改数，不构成防作弊保证；成绩判定以运行控制表与实践报告为准。

这句话在系统里出现三处、逐字相同：核对报告（txt 与 json）的**首行**、规则说明弹窗的「存档与完整性校验」一节、以及本节。它由 `src/utils/audit.ts` 的 `INTEGRITY_BOUNDARY` 单点导出，三处 import 同一份；`tests/integrityCopy.test.ts` 断言本节与弹窗确实含该常量原文。

`audit.ts` 的 `INTEGRITY_CAVEATS` 是两条**实测得出**的余地，同样逐字出现在核对报告首行之后与本节：

- 旧档（version<4）的"不符"不等于篡改：那一版可能存在没写进流水的现金变动，天然就可能对不平；判据只看流水，这类判定的条数由帧统计单列（「其中旧档 version<4 的判定 N 条」）。
- 同一毫秒内的手操是精度盲区：季度推进与主动交易若落在 Date.now() 的同一毫秒，那笔交易既不进重述串、也不进尾随流水，会报出一条并不存在的"账实不符"；人工点按隔着秒不会触发，脚本式连点或自动化才可能。

边界之外还要如实说明三点（都已在代码里核实）：

- **重演算只重推现金这一类账实关系**：判据是两侧独立重建——「Σ 全部 `flow`」与「期初种子 + Σ 重述串 + 晚于最新重述串的尾随流水」各自等于帧末现金。缺期初 `初始现金` 种子的帧报「起算链不完整」而不是「账实不符」；后者按证据分三类：流水条目与现金不符 / 季度重述串与现金不符 / 帧末现金或期初条目被改。报出的季度坐标取自该帧自带的快照，核对结论只是提示，**不阻断导入**。
- **指纹是线索不是锁**：包指纹覆盖整包字节（`digests` 自身除外，含存档名/企业名/createdAt），逐帧指纹只覆盖 `{id, timestamp, version, resetCount, state}`——只改存档名会动包指纹而不动逐帧指纹。本机算不出摘要时（换设备、非 HTTPS）一律记「哈希未计算」，绝不参与比值、更不印成"不一致"这条假证。改完数据再自己重算摘要的人防不住，它只把成本从"编辑一个数字"提高到"得懂格式并重算"。
- **旧档的判定是建议性的**：`version < 4` 的帧判据只看流水，重述串那一侧只作展示读数（措辞单点在 `CALIBER_TEXT`），因为那一版本就可能有无日志的现金变动。

### 报告怎么读

`导出核对报告（txt）` 给人快速读，`（json）` 给教师留存批注与脚本比对（`frames`、`summary`、`digestMismatch`、`digestSkipped`、`packageDigestScope` 等字段）。两份产物**同一数据源**：逐帧结论用预览当场算的那份，指纹判定用预览的异步哈希循环刚分好的两张表——报告只转录本机算过的结果，绝不重算一遍（换设备或非 HTTPS 时本机根本算不出）。文件名与存档包同一条规则：`企业1核对报告-第X年第Y季-YYYYMMDDHHmm.txt`，且 txt 正文第一组读数里就有一行 `文件名：…`（json 是同值的 `reportFileName`）——报告被转发、截图或打印出来后，正文要能对上它自己那个名字。

**包指纹那一行说的是声明，不是核实**：`包指纹：…（包内声明值；导入侧只重算逐帧指纹，整包指纹未重算）`。导入侧的异步循环逐个重算的是**逐帧**摘要，整包摘要（`digestPackage`）只在导出时算过一次，从不重算——所以「指纹不符：无」不等于整包没被动过（json 里另有 `packageDigestScope: "declared-not-reverified"` 供脚本判断）。包里声明的指纹若是 `unavailable:<原因>`（非 HTTPS 环境算不出摘要），报告与面板都印成人话「哈希未计算（非 HTTPS 环境）」，绝不把内部 token 原样印出来；措辞单点在 `audit.ts` 的 `digestUnavailableNote` / `digestSkipNote`。

导出报告与导出存档包一样有失败面：中途抛错会写进 `validationError` 并说得出原因（`报告导出失败：…`，取 `error.message`）。

## 项目结构

```
src/
├── app/                 # 页面（主界面 + 财务中心）
├── components/          # 生产/物流/营销/运营中心、规则弹窗、贴现面板、存档面板

├── config/              # marketDemand（订单池配置，教师可修改需求量）
├── types/               # TypeScript 类型定义
docs/
├── superpowers/specs/   # 设计规格
├── superpowers/plans/   # 实现计划
tests/                   # Vitest 单元测试（规则计算、控制表、端到端）
directions/              # 课程方向资料
```
